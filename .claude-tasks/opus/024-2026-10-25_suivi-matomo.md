# 024 — Suivi Matomo (site React + back-office EasyAdmin)

- **Modèle** : Opus
- **Justification** : intégration transverse (SPA React + Symfony), gestion des environnements (dev / préprod / prod) et des navigations côté client.

## Fichiers modifiés / créés

- `frontend/.env.production` (créé) : `VITE_MATOMO_URL`, `VITE_MATOMO_SITE_ID=13`, lus uniquement par `vite build`
- `frontend/src/lib/matomo.js` (créé) : `initialiserMatomo()` charge `matomo.js`, `suivrePage()` enregistre une page vue
- `frontend/src/main.jsx` : appel de `initialiserMatomo()`
- `frontend/src/components/Layout.jsx` : une page vue par changement de route (React Router ne recharge pas la page)
- `.env` : `MATOMO_URL` et `MATOMO_SITE_ID` vides (désactivé en dev et en test)
- `.env.prod` (créé) : valeurs Matomo, chargées avec `APP_ENV=prod` (préprod et prod)
- `src/Controller/Admin/DashboardController.php` : `configureAssets()` injecte le snippet dans toutes les pages EasyAdmin

## Résumé

Matomo est actif uniquement en ligne :
- **React** : actif seulement avec `import.meta.env.PROD` (build) ; le serveur Vite de dev ne lit pas `.env.production`.
- **Admin** : snippet ajouté seulement si `MATOMO_URL` est renseigné, ce qui n'est le cas qu'avec `APP_ENV=prod`.

Vérifications : `make lint`, `make test` (17 tests OK), build Vite contenant le tracker, chargement Dotenv simulé (dev → vide, prod → valeurs).
